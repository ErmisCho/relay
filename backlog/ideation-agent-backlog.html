Q1 · executor Open

Where does the code executor check out the repo?

Determines how secrets are handled and whether a dispatched task survives a closed laptop.

CloudA sandbox clones from the git host directly — tasks are durable and outlive the client, but the sandbox needs its own credentials.
LocalAn agent runs on a machine that already has the checkout — no extra secrets to provision, but the task dies if that machine sleeps or closes.
affects → Pydantic AI executor, DBOS workflow durability
Q2 · wake word Open

Pretrained wake phrase, or a custom-trained one?

Trades zero setup cost against an on-brand phrase — and the two require different tooling.

StockAn openWakeWord pretrained model — free, works today, no training pipeline.
CustomA trained phrase via Porcupine — on-brand wake word, but adds an account, a training step, and a second engine to keep on the client.
affects → §5 wake word component, first-run setup
Q3 · sessions Open

Do ideas resume across devices, or only on request?

Changes what the idea graph has to reconcile, and whether a session can silently pick up state the user forgot about.

AutoAn idea started on the desktop resumes on the laptop mid-thought — seamless, but the agent must merge context the user never re-stated.
ExplicitResumption is always a deliberate act — simpler state, but the user has to ask for continuity instead of getting it for free.
affects → §7 idea graph, sessions table
Q4 · barge-in Open

What happens when a completion report gets interrupted?

The agent announces a finished task at the next turn boundary — but the user may start talking before it's done. §6 doesn't say what the agent does with the rest of the report.

DropAbandon the announcement — the user's turn wins outright, the artifact link is still in the idea graph either way.
QueueHold the rest of the report and resume it at the next natural pause — nothing said gets lost, but it can feel like the agent is talking over the user's next thought.
affects → §6 commitment protocol, step 5 (Report)

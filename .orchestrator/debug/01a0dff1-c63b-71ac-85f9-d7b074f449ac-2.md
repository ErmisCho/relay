### Error

The process exits immediately with code 2 and emits no traceback. Collection order identifies test 48 as `tests/client/test_listener.py::test_two_real_sigints_shut_down_gracefully`; 47 dots precede process termination.

Environment: Windows 11, Python 3.13.5. Frequency: 2/2 full-suite runs. Control command `uv run pytest -q tests/client/test_listener.py -k 'not two_real_sigints'` passes 6 tests.

### Instrumentation data

- Collection item 48 calls `os.kill(os.getpid(), signal.SIGINT)` twice.
- `run_until_signalled()` uses `loop.add_signal_handler()` and silently skips installation on `NotImplementedError`.
- Python's Windows asyncio loop does not implement `add_signal_handler`, so `installed` remains empty.
- The first `os.kill(..., SIGINT)` therefore reaches Python's default SIGINT handler and terminates pytest with exit code 2.
- Every neighboring listener test passes when the real-signal test is deselected.

### Hypothesized root cause

`run_until_signalled` has no Windows fallback when `asyncio.add_signal_handler` is unsupported, so its own real-SIGINT test terminates the test runner instead of invoking the graceful shutdown path. · Confidence: high

## Phase 2 — Pattern

This is a platform capability gap, not a flaky test: Unix installs loop-level handlers, Windows enters the documented exception branch and installs nothing. The existing double-cancel test proves listener cleanup but cannot prove OS-signal handling. Skipping the test would preserve a real production defect for the Windows hackathon host.

A regression test already exists and is sufficient once the handler fallback is implemented.

## Phase 3 — Impact

Affected files:

- `src/relay/client/__main__.py` — process signal registration and restoration.
- `tests/client/test_listener.py` — existing real-signal integration test.

The fallback must restore previous process handlers after shutdown and must still ignore repeated signals while cancellation is underway. Unix behavior must remain unchanged.

## Phase 4 — Solution

When loop-level signal handlers are unavailable, install `signal.signal()` handlers that schedule the same `request_stop` callback on the running loop, remember prior handlers, and restore them in `finally`. Keep the current Unix `add_signal_handler` path. Verify the isolated real-signal test, the listener file, and the full suite.

## Resolution

Added a Windows `signal.signal` fallback with restoration of previous handlers. The test now uses `signal.raise_signal(SIGINT)`: Windows `os.kill(pid, SIGINT)` calls `TerminateProcess` rather than raising a console interrupt, so it could not test the handler. The real-signal test and final 524-test suite pass.

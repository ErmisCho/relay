# Debug session: local hardware tool returns data but voice answer becomes apology
Created: 2026-09-27T00:23:00Z
Session: 01a0dff1-c63b-71ac-85f9-d7b074f449ac

## Phase 1 — Root Cause

### Error

The opt-in zero-cost Ollama smoke test proves `hardware_capabilities` executes with the real host profile, but the spoken response is the generic apology instead of the specs.

```text
assert observed_results
spoken == "Sorry, I'm having trouble thinking right now..."
primary/fallback: Model returned no text or tool calls (finish_reason=stop)
```

### Reproduction

```text
RELAY_LLM_TESTS=1 uv run pytest -q tests/delegator/test_live_ollama.py -k hardware -s
```

Environment: local `ollama:gemma4:e4b`; no paid endpoint. Frequency: 1/1. Direct host probe reports AMD64 CPU, 95 GiB RAM, NVIDIA RTX 5070 + AMD Radeon Graphics.

### Instrumentation data

- `observed_results` is non-empty, proving model tool selection and execution succeeded.
- Both same-model attempts finish with `finish_reason=stop` but no visible text or tool call after receiving the tool result.
- The service correctly converts this provider defect into an audible apology, so the prior silent-success bug is fixed, but the user's requested specs are still lost.
- Hardware and weather are read-only tools whose `ToolResult.content` is already a complete, speakable answer. Their task explicitly says they answer directly in conversation and do not dispatch.

### Hypothesized root cause

The local thinking model sometimes emits only hidden reasoning on a tool-follow-up round under the voice token budget. Forcing another generation is unnecessary for read-only direct-answer tools and introduces this failure point. · Confidence: high

## Phase 2 — Pattern

The general internal-tool contract intentionally keeps results hidden because commitment and graph tools return control data. Hardware/weather differ: their outputs are user-safe final sentences. Streaming only explicitly marked direct-response tool results removes a redundant model round while preserving the hidden default for every safety-sensitive tool.

## Phase 3 — Impact

Affected: live hardware and weather answers, compound hardware+weather latency/reliability. Unaffected: commitment, dispatch, recall, status and all unmarked internal tools.

## Phase 4 — Solution

Add an explicit `direct_response` marker only to hardware/weather. When every same-round internal call is marked direct, stream the ordered results and end the turn; otherwise preserve the normal hidden tool-follow-up loop. Add an end-to-end contract test and rerun the real local hardware smoke check.

## Resolution

Marked only hardware/weather as direct-response tools. Their ordered results now stream without a redundant follow-up model call; all other internal tools remain hidden. The real local Ollama smoke test selected `hardware_capabilities` and spoke the observed AMD64 CPU, RTX 5070/Radeon GPUs and 95 GB RAM in 2.11 s. Final full suite passes.
